# Hi, I'm Yoko — Product Designer specialising in UX Architecture 👋

**User experience, system behaviour, data flows & implementation-ready specifications.**<br/>
**Web application architecture and implementation with React, Next.js and TypeScript.**

I design the user experience and the system behaviour behind it as one, and I also build and ship web applications. I work independently on a project basis: depending on what a project needs, I define how a product behaves, design its interface, or do both, with hands-on engineering support where needed.

I work through how a product behaves in use: what happens after an action, where data goes, which side validates what, and how someone understands an error and recovers. I bring what users are trying to do together with business rules and technical constraints, work through the trade-offs with the people responsible, and turn what we agree into specifications engineers can build from.

My hands-on engineering experience includes leading front-end architecture and implementation as the sole front-end engineer on a React and Next.js product, developing financial SaaS interfaces, and refactoring legacy game code.

When behaviour is difficult to judge on paper, I test it in a working prototype. My engineering background lets me carry decisions through to working code, whether I am writing the implementation or reviewing it with a team.

## Focus areas

- **Product behaviour:** interactions, UI states, validation, error handling and recovery flows.
- **Data flows and API agreements:** working with backend engineers to define data contracts and frontend/backend responsibilities.
- **Frontend architecture and implementation:** applications, reusable components and product interfaces in React, Next.js and TypeScript.
- **Accessibility in the codebase:** semantic HTML, ARIA, keyboard interaction, focus behaviour and screen-reader support, with automated and manual checks.
- **Specifications and implementation review:** documenting decisions and their reasoning, checking the working product against agreed behaviour, and resolving issues in code.

### Museum Mobile Guide — UX & API Specification (Concept)

![Museum guide artwork detail](images/museum-guide.png)

A screen and API specification for the mobile web guide of a fictional museum. Visitors open the guide via a QR code to find artworks, read or listen to content, and save works without creating an account.

The design covers offline access to loaded content, saving and synchronisation, past visits that retain the display arrangements of their dates, and artwork images that can no longer be shown after their permitted period. Includes 44 Figma screens across seven sections and a draft seven-endpoint API contract.

- [UX specification](https://ux.solastudio.studio/museum-guide-sample)
- [Figma design](https://www.figma.com/design/f2oPWX0hIw9fsvD9GT3ubS/Northlight-Museum)

### Returns & Refunds — UX & API Specification (Concept)

![Returns and refunds approval screen](images/returns-refunds.png)

A screen and API specification for a fictional online retailer's internal returns and refunds workflow, shared by returns inspectors, support agents and team leads.

The design covers role-specific queues, handovers, conditional approvals, delayed payment-provider results, and work left after a refund. Includes 11 Figma screen states, a 13-state return model and a draft five-endpoint API contract.

- [UX specification](https://ux.solastudio.studio/returns-sample)
- [Figma design](https://www.figma.com/design/DZUL2eR5fbadtdTwnLrrrY/Halden-Home-Refund-Dashboard?node-id=9-2&t=ZbKuHw7Ys8sGDGBl-1)
